Bigger changes & tickets: the suggested loop

1
Grill it
grill-with-docs stress-tests the approach
GLOSSARY.md · ADRs
→
2
Plan it
Criteria with a test each, simplified with ponytail
plans/<branch>.md
→
3
Approve it
You read and approve the plan file before code
your approval
→
4
Implement it
On a feature branch, subagents capped at Sonnet
feature branch
→
5
Verify it
Tests per criterion and pre-commit green
criteria ticked
→
6
Review it
pr-review checks the branch against the plan
verdict → PR

Not required, and nothing enforces it. It helps most when you don't know the codebase yet: grilling makes Claude dig through the code and ask you questions, so you understand it before anything changes. If you already know what to change and where, skip the loop and tell Claude directly; ponytail is always on. The plan file is committed with the change, so every step and every reviewer works from the same acceptance criteria.

Skills & agent that shape the coding experience

grill-with-docs

Interviews you in rounds, each question with a recommended answer. Writes resolved terms to GLOSSARY.md and hard-to-reverse decisions to ADRs.

/grill-with-docs

grilling

The interview alone, for a quick stress test of an idea without docs.

/grilling

ponytail

Forces the simplest solution that works and cuts speculative complexity. Loaded into every session by a hook.

always on

domain-modeling

Formats for the glossary and ADRs, so design decisions stay traceable. Used by grill-with-docs.

SKILL.md

agentic-kit-setup

One-time onboarding: CLAUDE.md files, secret-file rules and pre-commit checks, up to the Invent standard.

/agentic-kit-setup

pr-review agent

Read-only review on Opus: acceptance criteria from the plan file first, then correctness, then over-engineering with the ponytail lens.
